# TA Assistant

Moodle からダウンロードした Java の提出物を展開 → コンパイル → テスト実行し、結果を Excel / CSV にまとめる採点アシスタントの GUI 版です。
(旧 CLI 版: `TeachingAssistantAssistant`)

## 起動

```
./gradlew :desktopApp:run
```

前提: `javac` / `java` が PATH 上にあること (または画面の「JDK の bin ディレクトリ」で指定)。

## 使い方

1. **提出物ディレクトリ**: Moodle の zip を展開したディレクトリ (`<学籍番号> <名前>_<数字>_assignsubmission_file_` が並ぶ場所。形式はコンフィグの `submissionDirPattern` で変更可)
2. **コンフィグファイル**: 課題とテストケースを書いた YAML (書式は下記)
3. **出力先ディレクトリ**: 空欄なら提出物ディレクトリの親
4. 「実行」を押す

結果は「結果」「サマリー」タブで確認できます。

- 結果タブの一覧は学生ごとにまとめて表示します (見出しに判定ごとの件数。最初はすべて閉じていて、クリックで開閉)
- 結果タブではキーボードで手動判定できます: `A`=AC `W`=WA `T`=TLE `R`=RE `C`=CE (判定して次へ) / `U` or `BackSpace`=自動判定に戻す / `↑↓` or `J K`=移動
- 手動判定を変えたら「結果ファイルを出力」で出力し直してください
- 展開・コンパイル結果は `<提出物ディレクトリ>/workspace` に置かれます
- アプリが書き出すファイル (CSV・YAML) はすべて BOM 無しです。BOM 無しの UTF-8 CSV を Excel でダブルクリックして開くと日本語が文字化けするので、Excel で見る場合は「Excel (.xlsx)」か「CSV (Shift_JIS)」を選んでください

### 旧 CLI オプションとの対応

| CLI | GUI |
| --- | --- |
| `-l 0/1/2` | 実行ステップ |
| `-t` | 「テストを並列実行する」をオフ |
| `-m` | 結果タブでの手動判定 (テスト実行後にいつでも可能) |
| `-c` / `-s` | 出力形式 (CSV UTF-8 / CSV Shift_JIS) |

### コンフィグ編集

「コンフィグ編集」タブ (または設定パネルの「コンフィグを編集…」) で YAML を GUI で作成・編集できます。

- フォーム: 左の一覧で「全体設定」か課題を選び、右で編集します。入力ミス (不正な正規表現、重複した名前など) はその場でエラー表示され、上部の「エラー N 件」から該当箇所へ移動できます
- 「ディレクトリ名で試す」「出力例で試す」で、`submissionDirPattern` や `expect` の正規表現をその場で確認可能
- テストケースはカードの見出しをクリックで開閉。並べ替え・複製・削除は各見出しの「⋮」メニューから。削除は直後に表示される「元に戻す」で取り消せます
- YAML: 生成される YAML を直接編集することもできます (フォームに戻すと反映)
- 「保存して採点に使う」で保存したファイルが採点設定のコンフィグになります (採点に使用中のファイルは「保存」だけで反映)
- ショートカット: `Ctrl+S` 保存 / `Ctrl+Shift+S` 別名で保存 / `Ctrl+O` 開く / `Ctrl+N` 新規
- エディタで保存すると YAML 内のコメントは失われます

### 旧形式のコンフィグ

コンフィグの先頭には形式のバージョン (`version`) を書きます。現在は `version: 2` です。
`version` が無い・古いコンフィグはそのままでは読み込めず、採点を実行するとエラーになります。
アプリより新しいバージョンのコンフィグも読み込めません。

「コンフィグ編集」で開くと自動で現在の形式に変換され、変換内容が表示されます (この時点ではファイルは変更されません)。
「保存」で上書きすると、変換前の内容は `<ファイル名>.bak` に残ります。

| version | 変更内容 |
| --- | --- |
| 1 (`version` なし) | 旧 CLI 版の形式 |
| 2 | `version` を追加。`disablePackage` を廃止 (代わりに設定パネルの「実行前に workspace を初期化する」) |

## 判定 (AtCoder 方式)

| stat | | |
| :---: | --- | --- |
| AC | Accepted | 正答 |
| WA | Wrong Answer | 誤答 |
| TLE | Time Limit Exceeded | 実行時間制限内に終了しなかった |
| RE | Runtime Error | 実行時エラー |
| CE | Compile Error | コンパイルエラー |
| IE | Internal Error | システム内部エラー |
| NF | Not Found | 提出がない / ソースから課題を特定できなかった |
| CF | Conflict | 1つの課題に複数ファイルが該当し結果を特定できない (Summary のみ) |

AC / WA は正規表現による自動判定なので、詳細を必ず確認してください。

## コンフィグファイル

ソースコード中に `word` のどれかが含まれ、`excludeWord` がどれも含まれなければ、その課題の提出とみなします。
`expect` は「改行を空白に置換した標準出力全体」に対する正規表現で、**すべて**にマッチすれば AC です。

```yaml
version: 2                          # コンフィグ形式のバージョン (必須・先頭)
compileTimeout: 3000                # コンパイルのタイムアウト(ミリ秒)
runningTimeout: 5000                # 実行のタイムアウト(ミリ秒, 負なら無制限)
outputFileName: output              # 出力ファイル名(拡張子は自動)
# 提出ディレクトリ名の正規表現 (省略可。省略時は下記の Moodle 形式)
#   名前付きグループ id = 学籍番号 (必須), name = 氏名 (任意)
#   名前付きグループを使わない場合は 1番目 = 学籍番号, 2番目 = 氏名
#   ディレクトリ名全体にマッチしたものだけが対象になる
submissionDirPattern: '^(?<id>\S+)\s+(?<name>[^_]*)_.*assignsubmission_file_?$'
tasks:
  課題1:
    word: [課題1, 課題１, kadai1]
    excludeWord: ["前回課題"]
    testcase:
      - name: test1
        arg: "1 10"                 # コマンドライン引数 (ダブルクォートで空白を含められる)
        input:                      # 標準入力 (1要素 = 1行)
          - "1 2 3 4"
          - "5 5"
        expect:
          - '^.*(?<![-\d])45(?!\d).*'
```

## 構成

| 場所 | 内容 |
| --- | --- |
| `shared/src/commonMain/.../core` | ドメインモデル、コンフィグ、課題判定、自動判定、集計、CSV、採点パイプライン |
| `shared/src/commonMain/.../ui` | Compose UI と `AppController` (状態管理) |
| `shared/src/jvmMain` | javac / java の実行、zip 展開、Excel 出力、ファイル選択ダイアログ、設定の保存 |
| `desktopApp` | ウィンドウを開くだけ |

```
./gradlew :shared:jvmTest   # テスト (実際に javac / java を使う結合テストを含む)
```
