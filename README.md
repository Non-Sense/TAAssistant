# TA Assistant

Moodle からダウンロードした Java の提出物を展開 → コンパイル → テスト実行し、結果を Excel / CSV
にまとめる採点アシスタントの GUI 版です。 (旧 CLI 版: `TeachingAssistantAssistant`)

## 起動

```
./gradlew :desktopApp:run
```

前提: `javac` / `java` が PATH 上にあること (または画面の「JDK の bin ディレクトリ」で指定)。

## 配布用のファイルを作る

| 形式                                 | コマンド                                         | 出力先                                              | 実行する PC の Java |
|--------------------------------------|--------------------------------------------------|-----------------------------------------------------|---------------------|
| 実行ファイル (フォルダごと配布)      | `./gradlew :desktopApp:createDistributable`      | `desktopApp/build/compose/binaries/main/app/TAAssistant/` (`TAAssistant.exe`) | 不要 (同梱)         |
| インストーラー (Windows)             | `./gradlew :desktopApp:packageMsi` / `packageExe` | `desktopApp/build/compose/binaries/main/msi/` / `exe/` | 不要 (同梱)         |
| インストーラー (macOS / Linux)       | `./gradlew :desktopApp:packageDmg` / `packageDeb` | `desktopApp/build/compose/binaries/main/dmg/` / `deb/` | 不要 (同梱)         |
| 実行可能 jar                         | `./gradlew :desktopApp:packageUberJarForCurrentOS` | `desktopApp/build/compose/jars/TAAssistant-<OS>-<CPU>-<バージョン>.jar` | 21 以上が必要       |

- どの形式も、作った OS 向けのものしか作れません (Windows 用は Windows で、macOS 用は macOS で作る)。
  実行可能 jar も、画面の描画に使うネイティブライブラリを含むため OS ごとに別です
- 実行可能 jar は `java -jar TAAssistant-windows-x64-1.0.0.jar` で起動します
- 実行ファイル・インストーラーは Java のランタイムを同梱しています (約 155MB)。同梱するモジュールは
  `desktopApp/build.gradle.kts` の `modules(...)` で指定しています。依存ライブラリを変えたら
  `./gradlew :desktopApp:suggestRuntimeModules` で足りないものがないか確認してください
- Windows のインストーラーを作るのに必要な WiX は、ビルドが自動で取得します
- バージョンは `desktopApp/build.gradle.kts` の `packageVersion` で変えます。`windows { upgradeUuid }` は
  上書きインストールに使うので変えないでください
- どの形式でも、採点に使う `javac` / `java` / `javap` は同梱のランタイムではなく、PATH 上か画面で指定した JDK のものを使います。
  採点する PC には JDK が必要です

## 使い方

0. **プロジェクト**: 最初の画面で「新しいプロジェクト…」を選び、プロジェクトファイル (`.taa`) の保存先を決める
   (下記)
1. **提出物ディレクトリ**: Moodle の zip を展開したディレクトリ
   (`<学籍番号> <名前>_<数字>_assignsubmission_file_` が並ぶ場所。形式はコンフィグの
   `submissionDirPattern` で変更可)
2. **コンフィグファイル**: 課題とテストケースを書いた YAML (書式は下記)
3. 「実行」を押す

結果は「サマリー」 (最初に表示される画面) と「詳細」タブで確認できます。採点が終わるとサマリーを表示します。

結果ファイル (Excel・CSV) の書き出しは、実行後に必要なときだけ行います。右上の「結果を書き出す」で形式を選ぶと、保存先を選ぶダイアログが開きます。

- 初期位置は前回書き出したディレクトリ (初回は提出物ディレクトリの親)、ファイル名はコンフィグの `outputFileName` です
- CSV は 1 ファイルに収まらないため、選んだ名前に `-detail` / `-summary` を付けた 2 ファイルになります
- 書き出し後に表示されるファイル名から開けます。「フォルダを開く」もあります
- 前回書き出した形式には、メニューで印が付きます

- 実行のログは、「実行」の下の「ログ」 (行数と警告・エラーの件数を表示) から別の画面で開けます。実行中は進み具合も表示されます。「←」か
  `Esc` で戻ります。採点が失敗したときは上部のエラー表示の「ログを見る」からも開けます

- 詳細タブの一覧は学生ごと → 課題ごとにまとめて表示します
  (見出しに判定ごとの件数。学生は最初すべて閉じていて、学生・課題とも見出しのクリックで開閉)
  。課題はコンフィグの順で、課題を特定できなかったソースは「 (課題不明)」として最後に並びます
- 手動判定・課題の割り当てをした学生には、詳細タブの見出しとサマリーの「手動介入」列に「✎ 手動 N」「割当
  N」の印が付きます。絞り込みの「手動判定・割り当て」で該当する結果だけを表示できます
- 学生のページ: 詳細タブの学生の見出しの人型アイコン、結果の詳細の「学生のページ」、サマリーの学籍番号・名前から開けます
    - 「結果」タブ: 詳細タブと同じ一覧 (課題ごと) と詳細。手動判定 (キー操作も同じ)
      や、課題を特定できなかったソースへの課題の割り当てもここでできます
    - 「提出ファイル」タブ: 以下の一覧とプレビュー
    - 提出ファイルの一覧
      (元の提出ディレクトリのファイルと、展開したソース。ソースには判定された課題とコンパイル結果を表示)
      と、選んだファイルの中身 (行番号付き)
    - zip・jar・tar・tar.gz (tgz) は、展開せずに中の階層をツリーで表示します。採点時に展開されないもの
      (__MACOSX・.class、zip 以外の形式) は薄く表示します。7z・rar はプレビューできません
    - 「前の学生」「次の学生」で切り替え、「←」か `Esc` で採点画面に戻ります
    - 元の提出ディレクトリは、この機能を追加する前に採点した結果では分からないため、再実行すると表示されます
- 詳細タブではキーボードで手動判定できます: `A`=AC `W`=WA `T`=TLE `R`=RE `C`=CE (判定して次へ) / `U`
  or `BackSpace`=自動判定に戻す / `↑↓` or `J K`=移動 / `Enter`=実行 (手動で判定する課題)
- 手動判定を変えたら「結果を書き出す」で書き出し直してください
- 展開・コンパイル結果は `<提出物ディレクトリ>/workspace` に置かれます
- アプリが書き出すファイル (CSV・YAML) はすべて BOM 無しです。BOM 無しの UTF-8 CSV を Excel
  でダブルクリックして開くと日本語が文字化けするので、Excel で見る場合は「Excel (.xlsx)」か「CSV
  (Shift_JIS)」を選んでください

### プロジェクトファイル (.taa)

採点の設定 (提出物ディレクトリ・コンフィグのパス・オプション・前回の書き出し先)、課題の割り当て、採点結果
(手動判定を含む) を、コンフィグ (YAML) とは別のプロジェクトファイルにまとめて保存します。

- 変更は自動で保存されます (保存状態は設定パネルの上部に表示)。アプリを閉じるときも保存してから終了します
- 開き直すと、再実行しなくても前回の結果を確認・手動判定の続きができます。起動時は前回のプロジェクトを開きます
- 設定パネル上部の「⋮」から、プロジェクトの操作ができます
    - 新しいプロジェクト / 開く / 閉じる
    - 別名で保存: 今の内容を新しいファイルに保存し、以後はそちらを開いている状態になります
      (元のファイルも残ります)
    - 複製: 今の内容 (設定・割り当て・結果) を新しいファイルにコピーします。開いているプロジェクトはそのままです
    - 設定だけを複製: 結果と割り当てを含めずにコピーします (次の回の課題を同じ設定で始めるときなど)
    - フォルダを開く: プロジェクトファイルのあるフォルダを開きます
- `.taa` と同じフォルダ以下にあるディレクトリ・ファイルは相対パスで保存するので、フォルダごと移動しても設定は使えます
  (結果に含まれる workspace のパスは絶対パスなので、移動した場合はソースの表示に再実行が必要です)
- 再実行すると、テストケースの内容が変わっていない結果には前回の手動判定を引き継ぎます。実行を中止・失敗したときは前回の結果に戻ります
- 中身は gzip で圧縮した JSON (インデントなし・BOM 無し)。`gzip -dc xxx.taa`
  などで展開すれば中身を確認できます。圧縮していない JSON のファイルも開けます
- 形式のバージョン (`version`) を持ち、新しいアプリで作られたファイルは開けません

### ソースと課題の紐づけ (割り当て・解除)

ソースがどの課題の提出かは `word` / `excludeWord` で自動で判定しますが、詳細タブ (学生のページの「結果」タブも同じ) で手動で直せます。

- **割り当て**: NF のソースを選ぶと「課題を割り当て」が表示されます。課題を選ぶと、そのソースをその課題としてすぐにテストし、結果を置き換えます
- **紐づけの解除**: 課題の付いた結果を選ぶと「この課題から外す」が表示されます。1つの課題に複数のソースが当たって
  サマリーが CF になったときに、関係ないソースを外せます。テストは実行し直さず、その課題の結果を取り除きます。
  課題が1つも残らなければ、どの課題でもない (NF) になります
- **自動に戻す**: 手動で決めた結果では「課題の判定を自動に戻す」で、ソースの内容から判定し直してテストします (同じテストケースの手動判定は引き継ぎます)
- 手動で決めた課題はプロジェクトに保存され、再実行しても使われます。割り当てた結果には「 (割り当て)」が付きます

### 危ない可能性があるコードの確認 (実行前の検査)

提出されたプログラムを確認なしに実行しないよう、コンパイルした後に、そのソースから作られたすべてのクラス (入れ子のクラスを含む) を
JDK の `javap -c` で調べ、危ない可能性がある呼び出しを探します。見つかったソースはテストを実行せず「保留」にします。

| 種類                               | 例                                                                                              |
|------------------------------------|-------------------------------------------------------------------------------------------------|
| 外部プログラムの起動               | `Runtime.exec`、`ProcessBuilder`、`Desktop.open` / `browse`                                     |
| ネイティブコードの読み込み         | `System.load` / `loadLibrary`                                                                   |
| ファイルの書き込み・削除           | `FileOutputStream`、`FileWriter`、`RandomAccessFile`、ファイル名を渡した `PrintWriter`、`File.delete`、`Files.write` / `delete` / `move` など |
| ネットワーク                       | `Socket`、`ServerSocket`、`URL.openConnection`、`HttpClient` など                               |
| リフレクション・動的なコードの実行 | `Class.forName`、`Method.invoke`、`MethodHandles`、`ClassLoader`、`ScriptEngineManager`、`Unsafe` など |

- 保留した結果は未判定 (`??`) になり、詳細に見つかった呼び出し (種類・呼び出し先・場所) を表示します。絞り込みの「実行を保留」で一覧できます
- ソースを確認して問題がなければ、詳細の「ソースを確認して実行」でそのソースのテストを実行します。確認はソースのハッシュと一緒に
  プロジェクトに保存され、再実行しても聞き直しません。ソースが変わったら確認し直します
- 手動で判定する課題の「実行」も同じく、確認するまで実行しません。メソッド呼び出しを確認するテストは実行しないので保留しません
- 検査できなかったソース (javap が失敗したなど) も保留します
- 課題で使ってよいものは、課題ごとの詳細設定で実行を許可できます。コンフィグエディタでは課題の画面の下の「詳細設定」で選びます

```yaml
  ファイル入出力:
    word: [課題5]
    allow: [fileWrite]                     # 種類ごとに許可する
    allowCalls: [new Socket]               # 呼び出し単位で許可する (書き方は calls と同じ。クラス.* はそのクラスのすべてのメソッド)
```

  | `allow` に書く値 | 許可する種類                       |
  |------------------|------------------------------------|
  | `process`        | 外部プログラムの起動               |
  | `native`         | ネイティブコードの読み込み         |
  | `fileWrite`      | ファイルの書き込み・削除           |
  | `network`        | ネットワーク                       |
  | `reflection`     | リフレクション・動的なコードの実行 |

  検査できなかったソースは、種類では許可できません (確認して実行してください)

実行するときの被害を小さくするため、次のことも行います。

- 提出されたプログラムは、毎回作って捨てる一時ディレクトリを作業ディレクトリにして実行します (相対パスのファイル操作が提出物やプロジェクトに届かないように)
- タイムアウト・停止のときは、プログラムが起動した子プロセスもまとめて終了します
- 使えるメモリを `-Xmx1g` に制限します
- コンパイル時に注釈プロセッサを動かしません (`-proc:none`。提出物に紛れ込ませたプロセッサがコンパイル時に実行されないように)

注意: 検査は書かれている呼び出しを見るだけなので、手の込んだ回避までは防げません (そのためリフレクションなども対象にしています)。
また実行するプログラムは TA と同じ権限で動きます。確実に隔離したいときは、仮想マシンや権限を絞ったユーザーで実行してください。

### 旧 CLI オプションとの対応

| CLI         | GUI                                               |
|-------------|---------------------------------------------------|
| `-l 0/1/2`  | 実行ステップ                                      |
| `-t`        | 「テストを並列実行する」をオフ                    |
| `-m`        | 詳細タブでの手動判定 (テスト実行後にいつでも可能) |
| `-c` / `-s` | 「結果を書き出す」の形式 (CSV UTF-8 / Shift_JIS)  |

### コンフィグ編集

設定パネルのコンフィグ欄の下にある「編集…」「新規作成…」で開くコンフィグエディタで、YAML を GUI で作成・編集できます。

- 「編集…」は採点に使っているコンフィグを、「新規作成…」は新しいコンフィグを開きます。新しいコンフィグは保存後、エディタの上部から採点に使えます
- 採点に使うコンフィグを切り替えた後に「編集…」を押すと、切り替えた後のコンフィグを開きます。編集中のコンフィグに未保存の変更があるときは、保存するか確認します (キャンセルすると編集中のコンフィグを続けます)
- エディタは採点画面とは別の画面です。左上の「←」か `Esc`
  で採点画面に戻ります。戻っても編集中の内容は残り、未保存の変更があれば「新規作成…」の横に「●
  未保存の変更あり」と表示されます。未保存の変更があるときに「新規作成…」を押すと、保存するか確認します

- フォーム: 左の一覧で「全体設定」か課題を選び、右で編集します。入力ミス
  (不正な正規表現、重複した名前など) はその場でエラー表示され、上部の「エラー N 件」から該当箇所へ移動できます
- 「ディレクトリ名で試す」「出力例で試す」で、`submissionDirPattern` や `expect` の正規表現をその場で確認可能
- テストケースはカードの見出しをクリックで開閉。並べ替え・複製・削除は各見出しの「⋮」メニューから。削除は直後に表示される「元に戻す」で取り消せます
- YAML: 生成される YAML を直接編集することもできます (フォームに戻すと反映)
- 「保存して採点に使う」で保存したファイルが採点設定のコンフィグになり、採点画面に戻ります
  (採点に使用中のファイルは「保存」だけで反映)
- ショートカット: `Ctrl+S` 保存 / `Ctrl+Shift+S` 別名で保存 / `Ctrl+O` 開く / `Ctrl+N` 新規
- エディタで保存すると YAML 内のコメントは失われます

### 旧形式のコンフィグ

コンフィグの先頭には形式のバージョン (`version`) を書きます。現在は `version: 2` です。
`version` が無い・古いコンフィグはそのままでは読み込めず、採点を実行するとエラーになります。
アプリより新しいバージョンのコンフィグも読み込めません。

「コンフィグ編集」で開くと自動で現在の形式に変換され、変換内容が表示されます
(この時点ではファイルは変更されません)。
「保存」で上書きすると、変換前の内容は `<ファイル名>.bak` に残ります。

| version            | 変更内容                                                                                            |
|--------------------|-----------------------------------------------------------------------------------------------------|
| 1 (`version` なし) | 旧 CLI 版の形式                                                                                     |
| 2                  | `version` を追加。`disablePackage` を廃止 (代わりに設定パネルの「実行前に workspace を初期化する」) |

## 判定 (AtCoder 方式)

| stat |                     |                                                                  |
|:----:|---------------------|------------------------------------------------------------------|
|  AC  | Accepted            | 正答                                                             |
|  WA  | Wrong Answer        | 誤答                                                             |
| TLE  | Time Limit Exceeded | 実行時間制限内に終了しなかった                                   |
|  RE  | Runtime Error       | 実行時エラー                                                     |
|  CE  | Compile Error       | コンパイルエラー                                                 |
| TCE  | Test Code Compile Error | テストコードのコンパイルエラー (メソッドが無い・引数の型が違う、またはテストコードの誤り) |
|  IE  | Internal Error      | システム内部エラー                                               |
|  NF  | Not Found           | 提出がない / ソースから課題を特定できなかった                    |
|  CF  | Conflict            | 1つの課題に複数ファイルが該当し結果を特定できない (Summary のみ。詳細の「この課題から外す」で解消できます) |

AC / WA は正規表現による自動判定なので、詳細を必ず確認してください。

## コンフィグファイル

ソースコード中に `word` のどれかが含まれ、`excludeWord` がどれも含まれなければ、その課題の提出とみなします。
`expect` は「改行を空白に置換した標準出力全体」に対する正規表現で、 **すべて**にマッチすれば AC です。

```yaml
version: 2                          # コンフィグ形式のバージョン (必須・先頭)
compileTimeout: 3000                # コンパイルのタイムアウト(ミリ秒)
runningTimeout: 5000                # 実行のタイムアウト(ミリ秒, 負なら無制限)
outputFileName: output              # 書き出すファイル名の初期値 (拡張子は自動)
# 提出ディレクトリ名の正規表現 (省略可。省略時は下記の Moodle 形式)
#   名前付きグループ id = 学籍番号 (必須), name = 氏名 (任意)
#   名前付きグループを使わない場合は 1番目 = 学籍番号, 2番目 = 氏名
#   ディレクトリ名全体にマッチしたものだけが対象になる
submissionDirPattern: '^(?<id>\S+)\s+(?<name>[^_]*)_.*assignsubmission_file_?$'
tasks:
  課題1:
    word: [課題1, 課題１, kadai1]
    excludeWord: ["前回課題"]
    testcase:
      - name: test1
        arg: "1 10"                 # コマンドライン引数 (ダブルクォートで空白を含められる)
        input:                      # 標準入力 (1要素 = 1行)
          - "1 2 3 4"
          - "5 5"
        expect:
          - '^.*(?<![-\d])45(?!\d).*'
```

### テストコードを使うテスト

`testCode` を書くと、提出されたクラスの `main` を実行する代わりに、自分で書いた Java のテストコードを実行します。
提出されたクラスのインスタンスを作ってメソッドを呼び、戻り値などを `System.out` に出力して、`expect` で確かめます。
コンフィグエディタでは、テストケースの「テストの方法」で「提出された main を実行」「テストコードを実行」を選びます。

```yaml
  電卓:
    word: [Calculator]
    testcase:
      # main の中身だけを書く
      - name: add
        testCode: |
          Calculator c = new Calculator(10);
          System.out.println(c.add(1, 2));
        expect: ['^.*13\s*$']
      # クラス全体を書く (import やヘルパーメソッドを使うとき)
      - name: range
        testCode: |
          import java.util.Arrays;

          public class RangeTest {
              public static void main(String[] args) {
                  System.out.println(Arrays.toString(Calculator.range(3)));
              }
          }
        expect: ['^\[0, 1, 2\]\s*$']
```

- `public class 名前` を含めばクラス全体、含まなければ `main` の中身として扱います (`TaaTest__` クラスの `main(String[] args) throws Throwable` で包みます)
- `package` を書かなければ、提出されたクラスと同じパッケージに入れます。そのため import せずに呼べ、package-private のメソッドも呼べます。`package` を書いた場合はそのまま使います
- クラス名が学生によって違っても同じテストコードで呼べるよう、次のプレースホルダーを使えます (提出されたソースごとに置き換えます)

  | プレースホルダー     | 置き換え後                                                         | 例                |
  |----------------------|--------------------------------------------------------------------|-------------------|
  | `${class}`           | 提出されたクラスの名前 (ソースのファイル名 = public class の名前) | `Calc`            |
  | `${qualifiedClass}`  | パッケージ付きの名前 (パッケージが無ければ `${class}` と同じ)      | `mypkg.Calc`      |

  ```yaml
        testCode: |
          ${class} c = new ${class}(10);
          System.out.println(c.add(1, 2));
  ```

  `package` を自分で書いたテストコードからは `${qualifiedClass}` を使います。クラス全体を書くときは、自分のクラス名にも使えます (`public class ${class}Test`)
- 提出されたクラスを classpath に入れてテストコードをコンパイル・実行します。`arg` (`args`) と `input` (標準入力) も使えます
- テストコードがコンパイルできなければ TCE、例外が出れば RE です。TCE は提出されたソース自体のコンパイルエラー (CE) と区別します。
  メソッドが無い・引数の型が違うといった提出側の問題のほか、テストコード自体の誤りでも起きるので「要確認」に含めます
- 提出されたクラスと同じ名前のクラスをテストコードに書くと、テストコードの方が優先されます
- 詳細には、実際にコンパイルしたテストコード (パッケージ宣言などを補ったもの) を表示します。結果ファイルには `testCode` 列が末尾に追加されます
- テストケースごとにテストコードをコンパイルするので、main のテストより時間がかかります (1件あたり javac 1回分)

### メソッド呼び出しを確認するテスト

テストケースに `calls` を書くと、プログラムを実行せずに、指定したメソッドを `main` から**直接**呼んでいるか確認します。
すべて呼んでいれば AC、1つでも呼んでいなければ WA です。コンフィグエディタでは「テストの方法」の「メソッド呼び出しを確認」を選びます。

```yaml
      - name: Arrays.sort を使う
        calls:
          - Arrays.sort             # クラス付き (パッケージは省略可。java.util.Arrays.sort とも書ける)
          - new Scanner             # コンストラクタ
          - println                 # メソッド名だけ
```

- コンパイル済みのクラスを JDK の `javap -c` で調べます。コメントや文字列の中の文字には惑わされません
- `main` から呼んだ自作メソッドの中までは見ません (直接の呼び出しだけ)。`main` の中に書いたラムダの本体は `main` の一部として数えます
- メソッド参照 (`Arrays::sort`) は呼び出しとして数えません。自動ボクシング (`Integer.valueOf`) などコンパイラが入れた呼び出しは数えます
- 詳細には、指定したメソッドごとの結果と、`main` から直接呼んでいたメソッドの一覧を表示します。`main` が無ければ WA です
- 手動で判定する課題 (下記) の中でも、このテストは自動で判定します

### 手動で判定する課題 (GUI の課題など)

課題に `manual: true` を書くと、採点時にはテストを実行せず、テストケースごとに未判定 (`??`) の結果を作ります。
詳細から1件ずつプログラムを起動し、画面を確認して手動で判定します。
コンフィグエディタでは、課題の「テストケース」欄の「1件ずつ実行して手動で判定する」で切り替えます。

```yaml
  課題3:
    word: [課題3]
    manual: true                    # 自動では実行せず、1件ずつ実行して手動で判定する
    testcase:
      - name: カウント
        arg: "10"                   # 引数・標準入力・テストコードも使えます
        check: |                    # 確認すること (判定するときに表示)
          ボタンを押すとカウントが1増える
          リセットで 10 に戻る
```

- 詳細で結果を選ぶと「手動で判定する課題」の欄に「確認すること」と「実行」ボタンが表示されます。`Enter` でも実行できます
- 時間制限はありません。ウィンドウを閉じるなどでプログラムが終わると、標準出力・標準エラー出力・終了コードを記録します。終わらないときは「停止」で強制終了します (出力は記録しません)
- 同時に実行できるのは1件だけです。判定は通常の手動判定と同じボタン・キー (A / W / T / R / C) で行います
- 未判定の結果は「要確認」で絞り込めます。コンパイルエラー (CE) は通常の課題と同じく自動で判定します

## 構成

`shared` のパッケージ (`com.n0n5ense.taassistant` 以下)。`commonMain` に置き、JVM 固有の処理だけ
`jvmMain` に置いています。

| パッケージ        | 内容                                                                                                                 |
|-------------------|----------------------------------------------------------------------------------------------------------------------|
| `core.config`     | コンフィグ (YAML) の読み書き、旧形式からの変換、エディタ用の下書きと入力チェック                                     |
| `core.model`      | 判定・学生・ソース・コンパイル結果・テスト結果などのデータ型                                                         |
| `core.grading`    | 採点パイプライン、課題判定、自動判定 / jvmMain: javac・java の実行、zip 展開                                         |
| `core.report`     | 集計、CSV / jvmMain: Excel 出力                                                                                      |
| `core.project`    | プロジェクトファイル (.taa) の読み書き、課題の割り当て・手動判定の引き継ぎ / jvmMain: gzip                           |
| `platform`        | ファイル選択ダイアログ・設定の保存など、UI から使う OS 依存の機能                                                    |
| `ui.main`         | アプリ全体の ViewModel (`AppViewModel`)、設定パネル、タブ、ようこそ画面 (画面遷移は `App.kt` で Navigation 3 を使用) |
| `ui.results`      | サマリー・詳細タブ                                                                                                   |
| `ui.configeditor` | コンフィグエディタ                                                                                                   |
| `ui.student`      | 学生のページ (Navigation 3 の画面ごとに ViewModel を持つ)                                                            |
| `ui.log`          | ログの画面                                                                                                           |
| `ui.common`       | 共通の部品 (判定バッジ、メニュー、スクロールバーなど)                                                                |
| `ui.theme`        | テーマ (Material Theme Builder の出力)                                                                               |

依存の向きは `core.config` ← `core.model` ← `core.report` ← `core.grading` ← `core.project` ← `ui`
です (`core` は `ui` に依存しません)。
`desktopApp` はウィンドウを開くだけです。

```
./gradlew :shared:jvmTest   # テスト (実際に javac / java を使う結合テストを含む)
```
